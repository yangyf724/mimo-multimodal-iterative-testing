# 测试层级 DL / ML / FL / AL

矩阵除「模态」外的正交检查维度，取自业界多模态测试实践的 Data → Modality → Fusion → Decision。每个矩阵行可标注所属层；一次检查可跨层取证，但缺陷按**发现层**归类。

## 四层定义

| 层 | 代号 | 检查内容 | 典型问题 |
|----|------|----------|----------|
| 数据层 | DL | 输入/夹具/种子质量、扰动鲁棒性、脱敏完整性 | 脏夹具、形状漂移、脱敏漏网、扰动即崩 |
| 单模态层 | ML | 各 surface 自身功能与非功能 | 某 API 500、某 viewport 布局炸、CLI 退出码错 |
| 融合层 | FL | 跨模态一致：图文表数字、版本、流程状态一致 | 报告数字 ≠ 证据数字、版本号跨源不一致 |
| 决策层 | AL | 裁决信号完整、报告-证据一致、发布结论可追溯 | 信号缺字段、结论无法落到证据 ID |

## DL — 数据层

- **输入与夹具**：测试输入、种子、fixture 是否覆盖声明的数据形状。
- **扰动鲁棒性**：边界值、噪声、乱序、缺字段下行为是否可接受。
- **脱敏完整性**：与 `data-masking.md` 硬门联动；DL 发现脱敏缺口即硬失败路径。
- 证据：夹具清单、种子哈希、脱敏扫描报告、扰动用例结果。

## ML — 单模态层

- 各 surface（M1–M13）自身的功能与非功能检查。
- 证据 Floor 以模态目录为准（`matrix-rules.md` / `modality-*.md`）。
- ML 缺陷分级参考该模态「典型分级」，最终以 `defect-severity.md` 为准。

## FL — 融合层（跨模态一致门）

必须一致的事实包括：

- 同一事实跨**图 / 表 / 文 / 制品**一致。
- **版本号、人名、日期、URL** 跨源一致；不一致必须披露。
- 流程状态一致（如：缺陷状态、轮次、RC 哈希在各交付物中相同）。

**融合层不一致（例如报告数字 ≠ 证据数字）视为证据缺陷（≥P1），须先修复再裁决。**

- 修复前不得进入 Allow 路径。
- 无法修复的一致性冲突 → 按保守原则 Deny 或 Escalate（见 `adjudication.md`）。
- 禁止在不一致状态下宣称完成。

## AL — 决策层

- 裁决信号 `adjudication_signals.json` 字段完整、与报告指标一致。
- 报告结论句可追溯到证据 ID。
- 发布结论（Allow / Deny / Escalate）可追溯到 SIG/RPT/EVD/PRD 四项依据。
- AL 失败（信号缺失、追溯断链）→ 不得 Allow；补全或 Escalate。

## 层与缺陷/裁决的关系

| 情形 | 处理 |
|------|------|
| DL 脱敏缺口 | 硬门失败 → Escalate（见 `data-masking.md`） |
| ML 功能缺陷 | 按 P0–P3 分级进入修复/回归 |
| FL 不一致 | **证据缺陷 ≥P1**；先修复再裁决 |
| AL 不完整 | 不得 Allow；补全或 Escalate |
| 主观/无规则可述结论 | P3 或 Deferred，不得单独支撑 Deny/Allow 主路径 |

## 与其他文档的边界

- 模态细节 → `modality-*.md`
- 环境与生产 → `env-layers.md` / `prod-test.md`
- 分级与修复 → `defect-severity.md` / `fix-regression.md`
- 四项依据综合 → `adjudication.md`
